## myd — document review & rich explainers

When the user wants to review, comment on, or discuss a Markdown file—or asks for a plan/design/explainer they'll look at—write it to disk and run `myd view "/abs/file.md"` **without `--wait`**. Tell the user the review tab is open, ask them to return in chat when finished, and end the turn. Do not poll, narrate idle status, or keep a turn alive waiting for Done. On the user's next turn, run `myd comments FILE` first; ids come from there. Use `myd reply` / `myd resolve` and `myd set-block` / `insert`; never hand-edit CriticMarkup or endmatter. Hand revisions back with another nonblocking `myd view FILE`, then end the turn again. Use `--wait` only when the user explicitly requests synchronous waiting and the runtime can block without polling; cap it at 1800 seconds. If waiting yields and would require polling, terminate only the waiter and switch to the nonblocking handoff—the tab and server remain usable. Load the **myd** skill for rich fences, block editing, and annotation details; `myd help` / `myd guide <topic>` also work.
