## myd — document review & rich explainers

When the user wants to review, comment on, or discuss a Markdown file — or asks for a plan/design/explainer they'll look at — write it to disk and use `myd` (on PATH): `myd view "/abs/file.md" --wait` opens the viewer and blocks until they click Done Reviewing. When it exits: (1) run `myd comments FILE` first — that is where the item ids come from; (2) `myd reply FILE <id> "…"` / `myd resolve FILE <id>` and edit the source with `myd set-block`/`insert` — never hand-edit the CriticMarkup or endmatter; if you need something from the user, ask it in the thread with `myd reply`, not only in chat; (3) hand it back with `myd view FILE --wait` again. Load the **myd** skill (`/myd`, or `~/.claude/skills/myd/SKILL.md` · `~/.codex/skills/myd/SKILL.md`) for the workflow, block editing, rich fences (mermaid / vega-lite / html), and the annotation inventory; `myd help` / `myd guide <topic>` also work.
