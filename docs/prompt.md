## myd — document review & rich explainers

When the user wants to review, comment on, or discuss a Markdown file — or asks for a plan/design/explainer they'll look at — write it to disk and use `myd` (on PATH): `myd view "/abs/file.md" --wait` opens the viewer and blocks until they click Done Reviewing. When it exits: (1) run `myd comments FILE` first — that is where the item ids come from; (2) `myd reply FILE <id> "…"` / `myd resolve FILE <id>` and edit the source with `myd set-block`/`insert` — never hand-edit the CriticMarkup or endmatter; if a comment raises something only the user can answer, don't stop to ask in chat — put the question in the thread (`myd reply`) and hand back with `--wait`; they answer there; (3) hand it back with `myd view FILE --wait` again — including when you're waiting on their answer to a question; stop only when their Done note approves and nothing is pending. Load the **myd** skill (`/myd`, or `~/.claude/skills/myd/SKILL.md` · `~/.codex/skills/myd/SKILL.md`) for the workflow, block editing, rich fences (mermaid / vega-lite / html), and the annotation inventory; `myd help` / `myd guide <topic>` also work.
